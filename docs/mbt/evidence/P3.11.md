## Accepted boundary

The implemented vertical performs this exact local workflow:

1. preview and import an invented customer;
2. create a local Front Desk 14YD quote and contract;
3. expose only the current delivery front leg;
4. reject Flatbed and bind a current eligible asset to a type-Bin truck;
5. confirm only the unchanged persisted BIN assignment through the dedicated,
   authenticated Dispatcher boundary;
6. materialize the complete Driver manifest;
7. persist start, scan, photo, and completion while logically offline;
8. resume and apply the original device occurrence timestamps exactly once;
9. reconcile the physical movement and server-owned distance;
10. expose only the explicit successor, rebased from actual completion plus
    the contract rental days while preserving the accepted return window; and
11. calculate and approve local-only billing without posting externally.

An independent vertical generates immutable completed-load evidence for split
SO, repeated TO, and shared PO/VRMA references. Exact retries and independent
commands retain deterministic identities and exact-cent allocation.

The existing generic Dispatch save, restore, and direct/default confirmation
paths remain fail-closed for BIN snapshots. The normal HTTP Confirm route may
ignore only browser-derived `loadId` and `timing` on otherwise byte-equivalent
MBT stops; it confirms the locked persisted copy and never persists the
submitted comparison copy.
