DELIVERY REQUESTS · 简体中文

送货申请销售操作手册

从客户送货需求开始，完成运费计算、调度沟通与订单关联；随后在同一申请中跟进改期和送货说明。

适用：销售员工账号版本：2026 年 10 月 19 日时间：Toronto / 多伦多金额：CAD / 加元，税前
① 先计算，再提交

填写货场、货量和路线后，点击 Calculate charge。更改计费资料后重新计算。

② 预批准后，及时关联订单

在页面截止时间前关联有效 SO 或 TO，点击 Secure approval，确认状态变为 Secured。

③ 改期获接受后，才更新承诺

协商期间，原 Approved time 继续有效。每次处理后都核对保存结果。

01 / QUICK START

先掌握这四步

  1. 销售提交申请New request → 填资料 → Calculate charge → Submit request
  2. 调度回复时段直接预批准，或提出新时间；销售确认是否接受。
  3. 销售关联订单在截止前输入 SO / TO → Secure approval。
  4. 核实并持续跟进确认 Secured、Approved time 和订单编号；补充送货说明。
以 Secured（已锁定）作为完成订单关联的标志。

提交申请、调度预批准、接受建议时间，分别是不同步骤。销售仍须成功保存有效的 SO / TO 才能停止到期倒计时。实际车辆安排与送货进度继续由调度跟进。

02 / GET READY

进入页面与准备资料

  1. 使用销售员工账号登录 MBBS。在销售菜单中选择 Delivery Requests。页面路径为 /sales/delivery-requests，位于当前 MBBS 系统域名下。
  2. 确认账号与申请货场。销售按账号所属货场访问申请。同一申请货场的授权销售同事可以共同查看和跟进。
  3. 选择已有申请，或新建申请。列表用于查找申请，详情区用于查看资料和操作；点击 New request 开始填写。

开始前准备好

  • 申请货场、实际出货货场、货物类型及各货场数量。
  • 完整送货地址，或多站行程的各段取货与卸货地址。
  • 客户期望日期、同日不少于两小时的时间范围，以及现场要求。
  • 如需参考报价，准备 EST 编号；如已有订单，准备 SO / TO 编号供预批准后关联。
本手册对应销售菜单中的 Delivery Requests。

这个页面负责送货时段申请、运费估算和订单关联。所关联的 SO / TO 须已通过现有订单流程建立；本页面不会自动创建这些订单。Request Stock 内的 Delivery 功能另有操作流程。

03 / NEW REQUEST

新建申请：先填基本资料

点击 New request（新建申请） 后，逐项填写以下资料。

界面字段填写方法
Requesting yard
申请货场		选择负责本次申请的货场。可选范围取决于账号权限。申请保存后，此字段不能更改。
Load type
货物类型		选择 POS 或 BIN。每张申请只使用一种类型。切换类型后，重新核对数量与费用。
Customer (optional)
客户名称，可选		建议填写便于识别的客户名称，方便同事搜索和交接。
Trip type
行程类型		按实际需要选择 Single trip、Round trip 或 Multi-stop trip。详见下一节。
Quote (EST) number
报价单编号，可选		填写实际 EST 编号，例如 ESTB123 的格式，点击 Preview quote 核对。报价单须属于申请货场。预览后仍需自行核对申请中的地址、货量及其他资料。
Delivery address
送货地址		单程与往返须填写完整地址，建议包括门牌、街道、城市和邮编。多站行程改为逐段填写地址。
Request remarks
申请备注		写明调度需要了解的事项，例如现场限制、联系人及可收货范围。最多 5,000 字符。
申请货场与出货货场要分别核对。

Requesting yard 决定申请归属与权限；Outbound yard 表示货物实际从哪里出发。两者可以不同。

04 / LOAD & ROUTE

填写货量与行程

POS：整托与散托

单程或往返时，每个出货货场填写：

  • Full POS qty：整托数量。
  • Loose POS qty：散托数量。

两项均为非负整数，合计必须大于 0。系统按两项之和计算 POS 数量。

BIN：规格、材料与 Yard

选择 BIN size 和 Aggregate；材料选项包括 Gravel、HPE、Screening、Crusher Run。

Quantity (Yard) 填材料数量，须大于 0，最多两位小数。车次数由数量、所选 BIN 容量及当前配置计算。

单程：Single trip

填写客户地址，在 Yard outbound quantities 中录入各货场的出货量。点击 Add outbound yard 增加货场，最多 4 个，货场不可重复。

出货货场→客户地址

往返：Round trip

填写方法与单程相同。报价会加入从送货地址返回取货货场的路线；返程按 1 车次计费，往程按实际货量计算。核对报价中的 Return 明细。

出货货场→客户地址→取货货场

多站：Multi-stop trip

  1. 在 Trip legs 中按真实路线顺序填写每段的 Pickup（取货点）、Drop-off（卸货点）及 Quantity（该段运量）。
  2. 第一段的取货点须选择 MBBS 货场；最后一段的卸货点须选择 MBBS 货场。中间地址按实际路线填写，并核对相邻段是否衔接。
  3. 用 Add trip leg 增加路段，或用 Remove leg 删除。总路段数为 2–20 段。
  4. POS 每段填写正整数；BIN 每段填写正数，最多两位小数。切换行程类型后，逐段检查系统带出的初始数量。
MBBS 货场→地址 A→地址 B→MBBS 货场

多站详情中的 Total across trip legs 为各段数量之和。每一段按本段距离及所需车次计费。

05 / CALCULATE & SUBMIT

计算费用、填写时段并提交

  1. 点击 Calculate charge（计算运费）。查看税前加元总额、路线距离、送货车次，以及适用时的调货和返程明细。
  2. 核对多货场计费结果。单程或往返中，3445 与 2967 归为一个计费货场，合并数量后计算车次；涉及其他货场组合时，系统比较集中出货方案，采用最低合计运费。可展开 Compare consolidation yards 查看可用方案。
  3. 填写 Requested timeslot（申请送货时段）。选择 Requested date，输入 Start time 与 End time。使用多伦多当地时间和 24 小时制，例如 0800 或 08:00。
  4. 补充 Request remarks，点击 Submit request。提交成功后，记录申请编号，核对状态显示 Awaiting Dispatch，并检查已保存的地址、数量和日期。
时间范围必须在同一天，且至少相隔两小时。

例如 08:00–10:00 或 09:00–12:00；08:00–09:30 或 23:00–次日 01:00 不符合要求。申请、建议时间与改期表单均按此规则填写。

什么时候必须重新计算？

  • 更改地址、出货货场、数量、货物类型、BIN 规格、材料或行程后。
  • 系统提示报价过期，或费率、容量、路线资料发生变化时。提交前的运费计算结果有效期为 10 分钟。
  • 修改已有待处理申请，或将过期申请重新提交时。
计费逻辑示例 · 非实际报价

如果当前配置为 每车 26 POS，则 27 POS 需要 2 车次。3445 的 25 POS 与 2967 的 2 POS 会先合并为 27 POS，再计算车次。

实际容量、距离、费率和运费以本次 Calculate charge 的结果为准。此处只说明数量取整方式。

06 / DISPATCH RESPONSE

处理调度回复与截止时间

调度接受申请时间

状态变为 Pre-approved — orders needed。核对 Approved time 和到期时间，立即进入订单关联步骤。

调度建议其他时间

状态为 Proposed time。与客户确认后，点击 Accept proposed time；状态进入预批准，随后关联订单。

客户需要其他时段

在 Request another time 表单填写新日期、开始与结束时间；可在 Reply (optional) 写原因，然后提交。申请返回 Awaiting Dispatch，等待调度重新答复。

接受调度建议时间不会重新开始倒计时。

倒计时从调度预批准或提出建议时间时开始。默认预批准期限为 3 小时、默认到期前 1 小时提醒，但调度可以更改配置或该申请的截止时间。每次都以当前申请显示的具体截止日期和时间为准。

培训示例 · 同一天，多伦多时间
10:00
调度提出新时段；页面显示截止时间为 13:00。
11:30
销售点击 Accept proposed time。
此时仍须
在 13:00 前成功关联订单并点击 Secure approval。

如果截止时间临近而订单尚未准备好，在对话区联系调度，刷新后核对最新期限。普通留言不会改变截止时间或批准状态。

07 / SECURE APPROVAL

关联 SO / TO，锁定申请

只有进入 Pre-approved — orders needed 后，才出现首次关联订单的表单。

  1. 找到 Sales / Transfer Order linkage。在 Order 1 (SO / TO) 中填写真实订单号。
  2. 每个输入框只填一个编号。点击 ＋ 增加输入框，需要删除未保存的行时点击 ×。可混合填写 SO 和 TO，最多 50 个。
  3. 确认编号与本次送货内容相符，在页面截止时间前点击 Secure approval（锁定预批准）。
  4. 等待保存成功，核对状态为 Secured，出现 expiry clock stopped，并检查批准时段和全部关联编号。
订单类型关联时的要求
SO / Sales Order
销售订单		输入以 SO 开头、属于申请货场且可被系统读取的 Delivery 销售订单。自取类型的 SO 不适用。
TO / Transfer Order
调货单		输入以 TO 开头的有效、活动状态调货单。申请货场必须是该 TO 的发货货场或收货货场；不存在、已关闭或不相关货场的 TO 无法关联。

PO 与 EST 不用于锁定预批准。只关联有效 TO 也可以进入 Secured；送货说明编辑功能则按关联的 SO 提供。

锁定后增加、更换或解除关联

  • 增加：点击 ＋，填入另一个 SO / TO。
  • 更换：点击 Exchange，输入替换编号。
  • 解除：点击 Unlink，移除该行。至少保留一个有效订单。
  • 保存：点击 Save order links，再核对已保存的编号。
更换订单关联后，原批准时间保持不变。

如新订单带来地址、货量或路线变化，应先与调度协调申请内容。订单关联操作本身不会重新计算这些资料。

08 / CHANGE THE TIME

已锁定申请如何改期

对 Secured 申请，在 Delivery time change 中操作。

  1. 在 Request new timeslot 中填写新日期和时间范围，可附原因，点击同名按钮提交。
  2. 页面出现待处理新时间。若要调整提议，填写后点击 Update requested timeslot；若撤回，点击 Withdraw time change。
  3. 调度接受后，检查 Approved time 已更新，再向客户确认新时间。调度拒绝时，继续按原批准时段跟进。

调度提出另一个改期时段

查看 Dispatch counter-proposal，与客户确认后选择：

  • Accept Dispatch timeslot：接受调度提议，并更新批准时间。
  • Keep approved timeslot：保留原批准时间，结束这次改期协商。
  • 再次填写新时段，点击 Update requested timeslot：继续请求其他时间。
协商期间，原 Approved time 继续有效。

Time change pending 表示仍在协商。等待对方接受期间，原订单关联与已锁定状态保留，到期倒计时保持停止。

09 / DELIVERY DETAILS

补充送货说明，预览关联单据

按每个 SO 保存送货说明

  1. 在已锁定申请下找到 Delivery instructions，从 Linked Sales Order 下拉框选择目标 SO。
  2. 先查看系统显示的现有说明，再在 Extra delivery instructions 中补充到场联系、入口、卸货位置及现场限制。最多 5,000 字符。
  3. 点击 Save instructions，确认出现 Delivery instructions saved.。如有多个 SO，分别选择并保存。
  4. 需要附图或视频时，使用 Add instruction media 选择文件，或拖放到上传区域。等待文件显示在附件区，并打开核对；用 Remove file 删除错误附件。
附件规则说明
数量与大小每个 SO 最多 5 个文件，每个最多 25 MB；图片会在上传前压缩。
图片与视频图片：JPEG、PNG、WebP、HEIC、HEIF。视频：MP4、MOV、WebM。
只读情况SO 已完成卸货或进入终结状态时，送货说明变为只读；按页面提示联系调度跟进。

只有 TO 的申请不会显示 SO 送货说明区域。混合 SO / TO 的申请只列出可填写说明的 SO。

预览单据

  • Preview quote：查看已填写 EST 的客户、日期、地址、商品数量及包装字段。
  • Linked orders → Preview SO…：打开所关联 SO 的原始 PDF。
  • Linked orders → Preview TO…：查看 TO 的发货与收货货场、备注、商品及数量摘要。
  • 核对完毕点击 Close preview 返回。
将执行要求写入对应 SO 的送货说明。

与调度的即时讨论可放在对话区；入口照片、卸货位置等送货执行资料应保存到相应 SO。单据预览用于核对资料，不会替代订单关联步骤。

10 / DAILY FOLLOW-UP

沟通、提醒与查找申请

在申请内与调度沟通

在 Sales & Dispatch conversation 下方的 Reply to Dispatch 输入内容，点击 Send reply。每条消息最多 2,000 字符，显示发送人、团队与多伦多时间。

普通回复保存沟通记录。接受时段、改期、锁定、取消等业务操作，仍须使用对应按钮。系统状态记录可展开 Request history 查看。

处理更新提醒

  • 看到 Delivery updates 未读数量或提醒弹窗时，点击 Open request 查看最新详情。
  • 点击弹窗 Close 只是关闭提醒；打开并阅读最新申请后才更新已读状态。
  • 系统通知在浏览器支持并获授权、且 MBBS 页面保持打开时可用，包括后台标签页。日常仍应主动检查申请及截止时间。

搜索、筛选与刷新

  • Search requests：按申请编号、客户、地址或已关联的 SO / TO 查找。
  • Status：可勾选多个状态；清除勾选后显示全部状态。
  • Refresh：刷新列表；Refresh request：重新读取当前申请详情。
同事可能正在处理同一申请。

如果看到申请已更新或要求刷新，先保留尚未发送的文字，再刷新、阅读最新记录，确认是否仍需执行刚才的操作。

11 / EXPIRED & CANCELLED REQUESTS

过期重提、修改与取消

申请过期后继续办理

  1. 点击 Refresh request，确认状态为 Expired。到期未关联订单或调度手动结束未锁定申请，都可能进入该状态。
  2. 点击 Re-raise request。核对或更新地址、货量、路线及申请时段。
  3. 点击 Calculate charge 获取新费用，再点击表单中的 Re-raise request 提交。
  4. 同一申请编号和历史继续保留；等待调度重新批准，再在新的截止时间前关联 SO / TO。

需要修改申请资料

在 Awaiting Dispatch 状态点击 Edit request，修改后重新计算，并点击 Save request。申请货场不可更改。其他状态如需更改货物类型、数量、地址或路线，先联系调度协调；已锁定申请的时间变更按第 08 节处理。

不再需要本次送货申请

先核对申请编号、关联订单和现场安排，必要时与调度沟通，再点击 Cancel request。核对状态变为 Cancelled。

取消会结束本次申请，并解除关联订单。

取消申请不会自动关闭 NetSuite 中的 SO / TO，也不等于已处理车辆安排。已有订单或送货任务需要调整时，继续与调度及订单负责人协调。取消后的申请没有 Re-raise 操作；恢复需求时新建申请。

12 / FINAL CHECK

完成核对与常见问题

提交申请前

  • 申请货场、各出货货场、POS / BIN 类型及数量正确。
  • 地址完整，单程／往返／多站选择正确，所有路段和数量已复核。
  • 运费已重新计算，已核对总额和适用的调货／返程明细。
  • 日期与时段按多伦多时间填写，同日且不少于两小时。

向客户确认安排前

  • 状态已为 Secured，SO / TO 编号正确，到期倒计时已停止。
  • 核对 Approved time；存在待处理改期时，仍以当前批准时段为准。
  • 每个需要说明的 SO 已保存现场要求，上传附件已可打开。
  • 已阅读调度最新回复，需要跟进的车辆或现场事项已交接。

提交按钮不可点

检查必填资料，先点击 Calculate charge；再确认日期与时间有效，结束时间至少晚于开始时间两小时。修改计费资料后需再次计算。

系统提示运费过期或资料已改变

点击 Calculate charge 重新计算，核对金额后再提交。若无法取得路线或费率，检查地址及所选资料，并把完整报错交给调度或管理员。

找不到 Secure approval

先检查状态。Proposed time 需先接受建议时间；Awaiting Dispatch 仍需等待批准；Expired 需重新提交。

SO / TO 保存失败

核对每框一个正确编号、订单类型与货场权限，以及 TO 是否仍有效。检查批准是否到期。修正后重新保存，并确认详情显示的最终状态与编号。

点击提交后超时或网络断开

恢复连接后，先刷新或搜索已有申请，查看该操作是否已经保存。确认结果后再继续，避免重复新建。

预览失败，或送货说明不能编辑

检查 EST 是否属于申请货场、SO / TO 是否仍与申请关联，并刷新重试。只有 TO 的申请没有 SO 说明区域；已完成卸货或进入终结状态的 SO 按页面提示只读。

客户已在对话里同意，为什么时间没有更新？

对话记录用于沟通。接受建议时间或改期，须点击对应的接受按钮，随后核对 Approved time。
