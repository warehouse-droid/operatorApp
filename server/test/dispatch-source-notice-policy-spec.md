# Dispatch source notice specification

Spec approval: not obtained (autonomous run). Tier 3 safeguards for an additive API/display change; no new dependencies, migrations, commits, or review/driver mutation behavior.

Only orders currently assigned to physical stops on the saved plan qualify for source notices, including members of planned groups. Orders in the pool, retired/unplanned stored reviews and dispatcher-owned COs remain quiet. A notice requires a matching successful NetSuite receipt or exact native NetSuite sync audit evidence. A mismatched receipt or unrelated/dispatcher audit cannot prove a source change. Dispatcher PO/TO linking, PO allocations and CO changes do not require pickup-point re-confirmation. A genuine native NetSuite pickup/destination/cargo change on a planned order remains visible. Mixed notices show only the verified source changes, retaining token, acknowledgement and decision behavior. Read-only review projection adds visibility and displayed-change fields without deleting or rewriting existing audit/review records.

The page honors this eligibility for pending and reviewed notices, immediately hides an eligible review after locally unplanning its order, and keeps backward compatibility for older API responses during rollback. Routine successful order-feed refreshes are quiet; failures and existing explicit action/save/lease feedback remain visible. No added buttons; notices remain advisory and planning saves continue. Source/driver locks, decision freshness, authentication, quantities, photos, completed S1 and the immediate Split dialog must survive.

Failure model: local pickup mistaken for NetSuite -> real planned SO/TO/PO/CO fixtures and receipt/audit mismatch cases; genuine source edits hidden -> positive receipt and real sync audit examples; stale/unplanned notice -> stored-review and live browser unplan; mixed diffs -> verified change projection; history loss -> immutable snapshots/jobs/review ledger assertions; silent failure -> refresh error browser case; scope creep -> exact live image overlay and immutable service configuration.

Use the existing bounded disposable Compose stack in mbbs-tests.slice, with teardown registered before launch and removal of every test container/database volume/network. Keep logs. Add failing acceptance tests before runtime edits, run relevant source/driver/split regressions on both live baseline and candidate, compare static diagnostics, cover changed executable lines, kill four plausible manual mutations, run property tests and reverse-order checks. Capture the exact live image; deploy only verified runtime files with rollback and read-only live checks.

Clarification after real CO execution: a pending-load CO stores the dispatcher's chosen transit pickup while the source mirror still reports its original yard. The CO fixture therefore saves that dispatcher choice using the created CO metadata before comparing source notices. The initial test incorrectly expected the mirror yard to change immediately; the notice-suppression requirement is unchanged. Repeated native NetSuite edits must be traceable through their ordered sync audit changes from the older saved quantity to the current quantity.
