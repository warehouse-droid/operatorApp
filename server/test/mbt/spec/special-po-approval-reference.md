Acceptance scenarios:
1. A real PO with status A, Pending Approval or Pending Supervisor Approval keeps the Special request Confirmed, including when materials await production. Both Sales and SCM show a clear PO approval notice. The Confirmed filter and SCM alert count include it. Closed/completed cases retain their terminal stage.
2. Approved/open PO status from the current canonical NetSuite mirror takes precedence over the cached case status. Approval advances to the normal stock/Dispatch stage without creating another PO. Unknown or rejected approval does not release the request. Test-skipped orders keep their testing behavior.
3. Unapproved POs cannot create/select a Dispatch handoff or complete vendor pickup. Existing erroneous handoffs cannot bypass approval. Previously planned/completed work is not deleted. Read-only status updates make no NetSuite order mutation.
4. The SCM PO creation form places quantity, UOM, gross unit cost and vendor discount percentage in one desktop row; use a readable responsive layout on narrow screens. Preserve per-line percentages, explicit zero and the single consolidated NetSuite discount.
5. Once a real PO is approved, SCM can edit/clear its PO reference in the Special request. This is the existing local dispatch_ref / Packing Slip-Ref shared with PO Split and PO/TO Schedule, not a new private field or a change to the native NetSuite number. The current value reads back after refresh, and updates in the other surfaces are visible here.
6. Reference writes require SCM authorization, case revision, the previously displayed reference, and current PO approval. Concurrent/stale edits, invalid values, duplicate visible references, skipped/unlinked POs and closed cases reject without partial writes. Reuse the existing shared reference updater and retain its schedule/plan rewrites. Keep Special planning detection working after a reference rename. Record a case audit event and emit shared refresh events.
7. Preserve standalone REST PO creation, all previous discount behavior, requester/Sales Rep controls, stock checks and customer decisions. Do not alter live PO approval, commercial values or reference values while verifying. Publish only scoped code over the current images, preserving concurrent Dispatch work.
