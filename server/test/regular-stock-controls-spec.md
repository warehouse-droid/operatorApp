# Regular stock approval controls and processing dialog

User requirements: show NetSuite busy state; disable all buttons during waits; prevent SO reuse; approval expires after configurable 15 minutes; auto-approval gate sends all new requests to manual review when off; give specific manual-review reasons; replace native confirmation with an obvious centered dialog. User clarified: Sales can re-raise after expiry.

## Acceptance and policy

1. A centered application dialog shows checking / applying status during NetSuite calls. All page buttons are disabled, background interaction is blocked and repeated clicks cannot send another mutation. Buttons recover after success, cancel or error. During confirmation only the dialog Cancel / Confirm buttons are usable. Escape cancels a review; it cannot dismiss processing.
2. Every SO identity and reference may be consumed by one regular request only, enforced under a database lock and unique indexes. A rejected preview does not consume it. Same-request recovery remains idempotent and usable after the approval deadline. Cross-request reuse is rejected with the SO and existing request reference before any order write.
3. Approval validity defaults to 15 minutes, configurable as a positive whole number (1–10080 minutes). The timer starts when the whole request has its decisions and at least one approved item. Auto approvals start immediately. Settings apply to new approvals; existing deadlines are immutable. Preview and execution recheck expiry, including after a slow NetSuite read and while holding the request lock. A confirmation claimed within its valid window may finish/recover afterward.
4. Expired unused approvals remain in history and cannot link an SO. Sales sees Re-raise request. Re-raising rechecks fresh stock and current gate/lead/safety settings for the previously approved items; rejected/cancelled items remain closed. Re-raise requires the current request revision, creates an audit event, and cannot run after an SO has been claimed. A fresh manual review has no deadline until all decisions finish.
5. Auto-approval setting defaults on to preserve the current behavior. Off sends every new/re-raised request to manual review even when stock and lead conditions pass. Missing evidence and stock/lead checks remain fail closed. Invalid setting types / expiry values fail without changing settings.
6. Sales and SCM see each reason: gate disabled, required minimum hours, named item/source below safety with remaining/required quantity and units, or missing stock/safety evidence. Existing safety display and approval history stay available.
7. Completed action details, exact quantity messages, non-stock companions, authorization, request revisions, concurrency guards and TO retry idempotency remain intact. No live test order or quantity/location edit is authorized by verification.

## Failure model / setup

Tier 3: order duplication (database uniqueness + concurrent HTTP/service test), stale/expired approval (clock boundary/property + delayed-read test), expiry breaks recovery (existing retry tests with expired timestamp), gate ignores false (settings/API + generated conjunction), duplicate browser clicks / invisible waits (delayed network browser tests and disabled-button assertions), stale approval reset (revision/ownership tests), migration breaks current data (read-only duplicate audit and isolated migrate checks), inaccessible/unsafe dialog (keyboard/mobile/escaping checks).

Use the existing pinned Docker tools and a fresh disposable database. Add migration 240, dedicated approval-window/dialog helpers, test/spec/evidence artifacts and scoped deployment tooling. No dependencies, commits or external notifications. Deploy only this task's patch over the current live image, preserve runtime configuration, record additive migration and rollback. Spec approval: not obtained (autonomous run); the requested behavior and expiry disposition are explicitly supplied by the user.
