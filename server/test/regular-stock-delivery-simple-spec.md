# Simple regular-stock Delivery — acceptance specification

Spec approval: not obtained (autonomous run); implements the user's stated rules. Tier 3 because the change approves inventory transfers and issues external orders.

- New Delivery submissions require only From Yard, To Yard and Sales Order number. No customer, arrival, remarks or item entry. Pickup and Stocking keep their existing behavior.
- 3445 → 2967 and 2967 → 3445 automatically approve, create a TO and queue its existing yard print job. Routes with 150 or 12441 remain pending until SCM approves. Delivery uses this yard rule independently of Pickup's safety/lead-time settings.
- Read the existing SO on the server. Transfer its open material quantities to its Sales yard; exclude discount/service/subtotal rows. Preserve the SO's location, quantities and prices. Reject unknown/same yards, inaccessible destinations, invalid SOs, fulfilled/closed material, wrong SO yards, missing item/UOM data, and forged client item quantities.
- Save the SO snapshot and unique ownership before issuing anything. Duplicate submissions of the same SO and route return/resume the saved request; other routes or owners cannot reuse it. No TO or printing before manual approval. SCM approves/rejects the whole Delivery request; PO replenishment and line editing do not apply to this form.
- Retry failures using the saved route/order identity. Concurrent retries cannot create multiple TOs. A changed SO blocks execution. Printer failure leaves a visible retry state and reuses the existing TO. Completed retries reuse the existing print job.
- Preserve existing requests and the separate Pickup/Stocking flows. No database migration, dependency, remote API or printer configuration changes.

Failure model: incorrect auto-approval (all yard pairs/property tests), client tampering or yard access (HTTP/domain tests), duplicate/partial writes (SQL concurrency and retry tests), stale SO (snapshot tests), printer failure (real transfer service with isolated external boundaries), broken form (browser checks including mobile and Chinese).

Record a task baseline and source hashes without committing unrelated workspace work. Run the stock-request regression suites, strict core types, lint, coverage, mutation checks and browser execution with persisted runners. No new dependencies.
