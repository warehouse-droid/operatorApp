Sales editing of Special Request lines — Tier 3

Scope confirmed by the user: before Sales Order creation. Formal spec approval: not obtained (autonomous run). The existing issued-order adjustment process remains available after SO creation.

Acceptance criteria:

1. Sales can open an editor for existing material product names, quantities and original sales rates, plus PALLET quantity and sales rate, on an active request before any SO/PO is created, skipped or submitted remotely. PALLET remains the fixed item. Existing colour, size, detail specification, UOM, discounts, packing, customer, vendor, yard, delivery and Sales Rep are preserved.
2. Changing a material name or effective quoted quantity returns the same SPREQ to New enquiry. The changed material needs a fresh SCM stock check and customer decision. Unchanged material rows retain all their reviews and commercial values. Both unsent order drafts are invalidated. Previous changed-line review data is retained in an SCM-only audit event, preserving private costs and notes.
3. Changing only a material rate, PALLET quantity or PALLET rate preserves the request status/stage, SCM checks and customer decisions. The saved quote reflects the changes. A saved SO draft receives the new selling rates/PALLET charge with its conversions and discounts preserved; purchase costs remain unchanged.
4. A mixed edit containing a material name/quantity change restarts the enquiry. Numerical equivalents and trimmed unchanged names are no-ops: no revision, audit or draft changes.
5. PALLET quantity 0 removes its charge from the displayed case and quote and from a saved SO draft. Positive free PALLET is valid. The editor remains accessible for adding PALLET when its count is 0.
6. The endpoint requires authenticated Sales access, an authorized yard, the enabled workflow and the original revision. Closed/completed requests, existing/skipped orders, remote submissions, uncertain operations and pending reviews reject edits without writes. Concurrent saves and SO creation serialize on the same request lock.
7. Reject foreign/duplicate line IDs, empty/oversized names, invalid types, non-positive material quantities, fractional PALLET quantities, negative or unsupported rates and unsafe amounts before any write. A later SQL failure rolls back every line, PALLET, draft, revision and event change. Client fields cannot overwrite SCM review data, order state or request headers.
8. The Sales UI explains the status rules, confirms a restart in the existing centered dialog, keeps edits on validation/conflict errors, supports cancellation without writes, and fits desktop and phone widths. Conflicted editors must be reopened from the latest revision before saving.

Failure model: wrong reset classification (named acceptance tests and classification properties); stale review reuse (SQL field/evidence assertions); lost unaffected rows or private data disclosure (full row preservation and audience tests); stale/double draft prices (converted SO/quote/PDF assertions); partial saves (SQL fault injection); revision/order races (real concurrent database/HTTP tests); unauthorized/hostile writes (role/yard/gate and validation tests); broken UI/cancel behavior (real Chromium browser tests); unintended NetSuite writes (isolated direct-access-disabled runner and outbound fetch guard); unrelated deployments (live baseline, workspace delta overlay and complete runtime hashes).
